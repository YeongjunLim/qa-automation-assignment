# 문제3 — 함께 풀어나간 과정

> 최종 답변은 [REVIEW.md](REVIEW.md), [README.md](README.md), [`src/`](src)에 있습니다. 이 문서는 그
> 결과에 도달하기까지의 논의를 기록합니다.

## 1. Claude의 1차 리뷰 설명

Claude가 먼저 원본 코드를 안정성/유지보수성/신뢰성 3개 관점으로 나눠 12개 문제를 찾고, Page Object Model + 폴링 대기 + 실패 시 스크린샷 캡처 등으로 리팩토링한 결과를 설명했다.

## 2. 지원자가 Kotlin/UIAutomator를 몰라도 5개를 직접 찾아냄

지원자가 Kotlin과 UIAutomator를 써본 적이 없다고 밝히면서도, 테스트 코드만 읽고 아래 5개를 스스로 짚어냈다 — Claude의 12개 항목 중 핵심적인 것들과 거의 정확히 겹쳤다.

1. `textContains("치킨")` 등 찾는 대상이 하드코딩되어 유지보수/재사용에 불리함
2. `5000`, `3000` 매직 넘버가 대기시간을 나타내는데 일관성이 없음
3. `Thread.sleep(5000)`이 시간을 잡아먹는 부분이 될 것
4. **(Claude가 놓쳤던 관점)** 주석이나 Given-When-Then 구조가 없어서, 이 코드만 보고는 어떤 요구사항/백로그에 대한 테스트인지 알기 어려움
5. `assertNotNull`만으로 검증하는 건 말이 안 됨

4번은 Claude의 원래 리뷰에는 "단일 메서드에 책임이 뒤섞임(유지보수성)"으로만 잡혀 있던 것을, 지원자가 "요구사항 추적성" 관점으로 더 명확하게 짚어낸 것 — [문제2](../problem2-bmart-stock-api)에서 TC-ID로 요구사항을 매핑했던 것과 같은 원칙임을 확인했다.

## 3. 나머지 후보 4개에 대한 논의 — 대부분 기각/재분류

Claude가 원래 리뷰에서 찾았던 나머지 항목 중 4개를 "6번 후보"로 제시했고, 지원자가 실무 경험을 바탕으로 하나씩 반박/재조정했다.

- **클릭 가능 여부 미확인**: 지원자 — "스크립트를 작성했다면 이미 누를 수 있는 상태니까 저렇게 썼을 것"이라고 반박. Claude가 인정 — UiAutomator는 앱이 idle 상태가 될 때까지 기다린 후 노드를 찾기 때문에 대부분의 경우 실제로 문제없다. "반드시 고쳐야 할 버그"가 아니라 "선택적 방어 개선"으로 격하.
- **팝업/다이얼로그 미고려**: 지원자 — 실무에서는 "Suite Setup"으로 앱 시작 시점에 한 번 처리했을 것이라고 제안. Claude가 이 아이디어에 "1회성 다이얼로그는 Suite Setup, 상시 발생 가능한 배너는 각 화면 진입 시 방어적 dismiss"로 2단 구조를 제안했으나, **최종적으로 지원자가 이 항목 자체를 핵심 목록에서 빼기로 결정**.
- **결제 성공/실패 분기 없음**: 지원자 — "이건 애초에 주문이 성공하는 케이스를 검증하는 테스트이고, 실패하면 '접수 대기'를 못 찾아서 `assertNotNull`이 정상적으로 실패한다"고 반박. Claude가 이 반박이 맞다고 인정하고, 원래 주장(성공으로 오판될 위험)을 정정 — 실제 가치는 "정확성 문제"가 아니라 "실패 시 왜 실패했는지 메시지가 불명확하다는 유지보수성/진단속도 문제"로 재분류.
- **테스트 데이터 정리(cleanup) 없음**: 지원자 — "스크립트를 어떻게 구성하느냐에 따라 필요 여부가 달라진다"고 조건부로 평가. Claude가 동의.

## 4. 최종 확정 — 5개로 압축

지원자가 "6번(팝업)은 빼고 1~5만 하자"고 결정. 최종적으로 핵심 문제는 아래 5개로 확정됐다.

1. 부분일치 셀렉터 하드코딩
2. 매직 넘버(대기시간) 일관성 없음
3. `Thread.sleep` 고정 대기
4. 요구사항/Given-When-Then 주석 부재 (지원자가 발견)
5. `assertNotNull`만으로는 검증 불충분

REVIEW.md와 README.md를 이 5개 기준으로 재작성했고, 클릭 가능 여부 확인/결제 분기/스크린샷 캡처/사전조건 보장/데이터 정리 관련 코드는 "핵심 5개와는 별도인 방어적 개선"으로 표기를 바꿔 코드에는 남기되 정식 문제 목록에서는 뺐다.
